薪慰是一款桌面工资进度小工具。用户填写月薪和作息，就能随时看到今天、本月已经赚了多少。核心体验是瞥一眼桌面，看见时间变成收入，获得一点即时安慰。

本文件是合并两份方案及交叉审查结论后的唯一开发需求基线。第一版围绕月薪估算、桌面小窗和可靠恢复展开；采用“小窗＋设置”，首次配置后直接显示小窗。交叉审查报告保留为决策记录，发生差异时以本文件为准。

## 2 定位和产品目标

### 2.1 目标用户与场景

主要用户是领取固定月薪、作息相对稳定、愿意在电脑桌面放一个小工具的上班族。

| 场景 | 用户想做什么 | 产品回应 |
| --- | --- | --- |
| 工作中短暂走神 | 看看今天已经赚了多少 | 桌面小窗直接显示今日金额 |
| 下午觉得时间难熬 | 得到一点即时反馈 | 数字自然增长，提示距离下班的时间 |
| 午休或下班 | 确认工具理解自己的作息 | 显示对应状态，金额停止增长 |
| 重启或休眠后回来 | 接着看现在的工资进度 | 根据时间和配置重算，无需补打卡 |
| 开会、共享屏幕 | 隐藏工资数值 | 一键隐藏金额，状态继续显示 |
| 使用另一种桌面系统 | 获得一致的计薪结果 | Windows 与 macOS 使用同一计薪核心 |

### 2.2 目标

1. 首次设置尽量在一分钟内完成，并能立刻看懂今日金额。
2. 小窗能长期放在桌面，不抢焦点，不打断输入。
3. 相同配置和时间始终得到相同结果，关机、休眠、隐藏窗口都不改变计薪口径。
4. 安装完成后，核心功能完全离线可用。
5. 后续增加 macOS 时，主要改动集中在系统集成及发布流程。

### 2.3 产品边界

薪慰显示的是工资时间进度估算。用户填税前工资就展示税前估算，填到手工资就展示到手估算。产品不计算个税、社保、公积金、绩效、奖金或实际发薪，也不读取公司考勤。

首版假设用户在当月整月任职、领取固定月薪。中途入职、离职、无薪假和加班工资不自动折算。日期设置表示“把固定月薪分摊在哪些时间”，不表示公司认可这些日期的工资待遇。

### 2.4 首版不做

账号、服务端、云同步、移动端、Linux 发布、排行榜、社交社区、AI 功能、付费系统、复杂统计报表、考勤采集、键鼠监控、自动识别摸鱼、自动识别加班、自动节假日同步。

这些能力不进入首版开发依赖。

## 4 计薪口径

### 4.1 首版采用的规则

把填写的月薪，按当月计划工作时长均匀分摊。只有计划工作区间内，金额才增长。午休、下班后和休息日停止增长。

采用这个规则，工作日数量不同的月份会有不同的日薪和时薪，但一个完整月份的估算总额等于填写的月薪。设置页始终显示一句解释：“按本月计划工作时长分摊月薪。”

首版固定使用人民币及 `Asia/Shanghai` 计薪时区。系统显示时区变化不改变作息所属日期；数据结构保留时区字段，为后续扩展留出位置。

### 4.2 默认作息与日历

- 每周工作日：周一到周五，可任意选择一至七天。
- 上班时间：09:00；下班时间：18:00。
- 午休默认开启：12:00 至 13:00；可关闭。
- 每个工作日使用相同作息；首版不支持跨夜时段。
- 内部以不重叠的工作区间表示作息；设置界面先只开放上下班和一个可关闭的午休，不开放任意多段及逐星期不同作息编辑。
- 日期覆盖优先于每周规则。将周六设为工作日后，使用同一套作息。
- 日历仅按每周规则初始化，不自动识别法定节假日或调休。
- 当前月可手工覆盖日期，设置页明确提示“节假日和调休请按需调整”。

### 4.3 公式

设 `S` 为用户输入的月薪，`Wm` 为本月所有计划工作区间的集合；午休已从区间中排除。所有区间使用左闭右开形式 `[start, end)`。

```text
Hm = 本月所有计划工作区间的总秒数
Em(t) = 本月所有计划工作区间中，截至当前时间 t 已经过的秒数
Ed(t) = 今天所有计划工作区间中，截至当前时间 t 已经过的秒数
Hd = 今天所有计划工作区间的总秒数

本月已赚 = S × Em(t) / Hm
今日已赚 = S × Ed(t) / Hm
今日可赚 = S × Hd / Hm
每小时参考值 = S × 3600 / Hm
今日进度 = Ed(t) / Hd                 当 Hd > 0
本月进度 = Em(t) / Hm
```

对于任一区间 `[a,b)`，已过秒数为 `max(0, min(t,b) - a)`，再对相关区间求和。`t` 使用真实时间戳，不使用动画运行时长。

月初上班前为零；最后一个计划工作区间结束后，本月金额恰好达到月薪。上限分别为本月月薪及今日可赚金额。休息日的今日金额和今日目标都为零，今日进度显示“休息日”，避免除零。

若本月没有任何工作区间，显示“本月没有设置工作时间”，不展示有效金额、时薪或进度，保留进入设置的入口。

### 4.4 精度与刷新

月薪以整数分保存。当前时间戳向下取整到秒后计算，使用整数秒与精确分数保留完整精度；今日、本月及日目标固定显示两位小数，采用非负金额四舍五入（half up），不提供小数位配置，不逐秒累加已经取整的金额。TypeScript 的金额乘法使用 `BigInt` 等精确整数运算，跨进程或写文件时以十进制字符串序列化大整数，避免大额工资超过安全整数范围。

小窗可见时，每秒从当前时间重新求值。数字不保证每秒变化一分钱；工资较低时，多个刷新周期才变化属于正常结果。动画只平滑显示结果，不作为金额数据来源。工作区间内可显示理论秒薪（四位小数），非工作区间显示“暂停计薪”，不继续展示带加号的增长速率。

每日展示金额各自取整后，相加可能和本月总额相差几分钱。本月总额始终从原始总时长计算，不把每日展示值相加。计算说明中解释这一点。

例如1元月薪分摊21个等长工作日，每日显示0.05元，展示值相加为1.05元，但本月最终仍为1.00元。精确速率仅用于计算，不能先截断秒薪再参与金额计算。零工作时长返回不可计薪状态，不生成整数金额快照。

### 4.6 设置修改和月份规则

首次安装时，直接按当前月月初至当前时间计算。因此中午第一次打开就能看到上午的进度，无需从安装时间起步。

工资或作息修改默认作用于整个当前月，并更新以后月份使用的默认模板。保存前展示修改前后的“今日已赚、本月已赚、本月计划工作日数、本月总工作时长”，按钮写明“保存并重算本月”。取消不改变现有配置。金额因规则改变而下降时，允许如实显示新值。预览与提交使用同一时刻比较规则差异，提交成功后再按真实当前时间刷新；若编辑期间跨月，刷新预览后再允许提交。

日期覆盖只影响对应月份；改变日期数量会同时改变本月分母和日目标，使用相同的保存预览。这个功能不计算请假扣款。

设置编辑期间跨月时，暂停提交并提示“月份已变化，请重新查看本月设置”。保留月薪及每周作息草稿，放弃未提交的旧月日期覆盖草稿，重新载入新月日历；提示中明确告知旧月日历修改未保存。已有的正式配置不受影响。用户查看新月预览后才能提交，不能把旧月日期误写进新月。

例如第4.5节的配置在11月3日10:30本月已赚950.00元，将未来的11月7日设为工作日后，本月变为176小时，同一时刻的本月已赚变为906.82元。预览必须解释这是固定月薪重新分摊，补班没有增加月薪。

首版只保存当前薪资与每周作息规则、按完整日期标识的日历覆盖，不保存薪资变更历史或历史月快照。月计划由当前规则、目标月份及匹配该月的日期覆盖即时生成；日期覆盖不会自动复制到下个月。离线跨月后直接计算当前月，无须补建经过月份的记录。

系统时间回拨到过去月份时，使用当前规则重新生成该月计划；结果不代表当时的历史工资。首版不提供历史审计能力。按日期覆盖可以保留在本地配置中，但编辑入口仅操作当前月；清除数据时统一删除。

## 5 首次使用与日常流程

### 5.1 首次使用

1. 打开应用，看到产品说明：“把工资进度放在桌面上。”
2. 输入月薪，选择“税前 / 到手 / 自定义口径”。默认税前；只改变标签。
3. 确认默认工作日和作息，可展开“调整作息”。
4. 看到预览：本月工作日、每天可赚及当前时间已赚。
5. 点击“开始看看”，保存配置并直接显示桌面小窗，设置窗口关闭。
6. 小窗显示当前时间的今日金额；用户无需再点击“开始计时”或“放到桌面”。

无需账号或联网。月薪不预填真实值；“试试示例”可临时使用 ¥16,800 展示，明确标注“示例”，退出示例后回到未配置状态，示例不写入正式配置。

### 5.2 日常使用

已设置的用户主动启动应用时显示或恢复小窗；开机启动时遵循“启动后显示小窗”偏好，默认开启，关闭后只驻留托盘。重复主动启动应找回现有小窗。计薪不依赖用户点击“上班”或“暂停”。

需要调整时，从小窗菜单或托盘进入设置；完成修改后，小窗同步重算。关闭窗口回到托盘；选择托盘“退出薪慰”才结束进程。退出后经过的计划工作时间仍在下次启动时计入估算。

## 6 页面与信息结构

全应用只有一个桌面小窗和一个普通设置窗口，加系统托盘菜单。首次设置复用设置窗口，不创建独立仪表盘。

### 6.1 小窗信息结构

按从上到下的顺序展示：

1. 顶部：薪慰、金额隐藏按钮、设置入口。
2. 当前状态：计薪中 / 午休 / 下班 / 休息日；配一个简短时间提示。
3. 主数字：今日已赚，大号等宽数字，人民币符号和小数层级稍弱。
4. 今日进度：进度条及“今日可赚 ¥800.00”一类辅助信息。
5. 次要信息：本月已赚；理论时薪、完整月薪和计算说明放在设置中查看。
6. 简短趣味文案可关闭，不额外增加窗口。内容过多时减少辅助内容，保留金额、状态和操作入口。

休息日不显示一个毫无意义的 0% 进度条；改为“今天休息，本月已赚……”的辅助提示。

### 6.2 桌面小窗

建议默认逻辑尺寸为 280 × 180，首版固定尺寸，允许设计阶段根据实际排版统一调整。默认展示今日金额、本月金额、状态，以及悬停或键盘聚焦时出现的菜单入口。

- 拖动明确的空白区域或标题区域移动，按钮不参与拖动。
- 首次打开位于当前屏幕右上角安全区域，不覆盖任务栏。
- 首次使用置顶默认开启，菜单提供明显开关；以后记住选择。
- 不抢焦点，不因金额更新而弹到前台。
- 关闭小窗只隐藏小窗，托盘保留。
- 位置按显示器和缩放信息保存；屏幕拔出或位置越界时移回可见屏幕。
- 暂不做鼠标穿透、嵌入桌面壁纸、全屏游戏覆盖或多虚拟桌面强制显示。
- 金额过长时使用两行或缩小至可读下限，不能裁掉整数或只显示省略号。

### 6.3 设置

| 分组 | 字段 | 规则 |
| --- | --- | --- |
| 工资 | 月薪 | 必填，¥0.01 至 ¥99,999,999.99，最多两位小数 |
| 工资 | 工资口径 | 税前 / 到手 / 自定义；自定义标签最多 12 个字符 |
| 作息 | 每周工作日 | 至少选一天，支持周六、周日 |
| 作息 | 上下班 | 分钟精度，同一天，上班严格早于下班 |
| 作息 | 午休 | 可关闭；开启时满足上班 < 午休开始 < 午休结束 < 下班 |
| 作息 | 计薪时区 | 首版只读显示“北京时间 Asia/Shanghai” |
| 本月日历 | 日期类型 | 工作日 / 休息日 / 跟随每周规则，仅当前月 |
| 显示 | 文案模式 | 普通默认，可切换窝囊费文案 |
| 显示 | 趣味文案 | 可关闭，关闭后不出现占位文案 |
| 显示 | 金额隐藏 | 默认关闭，状态跨重启保存 |
| 显示 | 主题 | 首版跟随系统，单独主题选择为后续功能 |
| 桌面 | 小窗置顶 | 首次开启，其后记忆 |
| 启动 | 开机启动 | 默认关闭，用户主动开启才注册 |
| 启动 | 启动后显示小窗 | 默认开启；关闭后仅影响开机自动启动，主动启动仍显示小窗 |
| 数据 | 清除本地数据 | 明确确认后清除规则、日期覆盖和位置，再回到首次设置 |
| 关于 | 版本与计算方式 | 显示版本、估算说明及本地数据说明 |

金额输入可规范化常见全角数字，接受用户粘贴的合法千分位；明确拒绝负数、空值、科学记数法、NaN、Infinity 及超出上限的值。错误直接显示在对应字段下方，保留用户输入。

设置未保存时关闭或返回，提示“放弃本次修改 / 继续编辑”。与计薪无关的偏好可即时保存；工资、作息及日历作为一个草稿批次预览后提交，避免每改一个字段就改变金额。

### 6.4 系统托盘

Windows 左键显示或激活小窗，右键打开菜单。托盘提示只显示应用名及状态，始终不包含工资或速率。

菜单顺序：显示或隐藏桌面小窗、小窗置顶、隐藏或显示金额、设置、退出薪慰。置顶项在小窗未显示时仍可保存偏好；托盘不提供工资摘要，避免旁路暴露。

首次关闭普通窗口时，显示一次“薪慰仍在托盘，右键图标可退出”的提示。托盘初始化失败时，关闭窗口应提供直接退出路径，不能留下用户找不到的后台进程。

## 7 状态与文案

### 7.1 状态优先级

配置缺失或异常优先于所有作息状态；有效配置下，按计薪时区的日期和时间决定状态。

| 条件 | 状态 | 金额行为 | 时间提示 |
| --- | --- | --- | --- |
| 无正式配置 | 等待设置 | 不显示真实金额 | 设置工资，开始看看 |
| 本月总工作时长为零 | 缺少工作时间 | 不显示有效估算 | 去调整本月日历 |
| 今天是休息日 | 休息日 | 今日为零，本月保持 | 下次上班时间，若已知 |
| 今天工作，上班前 | 还没上班 | 今日为零 | 距离上班还有…… |
| 位于工作区间 | 正在计薪 | 随时间增长 | 距离下班还有…… |
| 位于午休区间 | 午休中 | 保持午休前金额 | 距离下午开工还有…… |
| 下班及之后 | 今日收工 | 保持今日完成金额 | 今天辛苦了 |

“距离下班”按墙上时间计算，包含尚未经过的午休；如展示“剩余计薪时间”，必须单独命名并排除午休。首版只展示前者，避免两个倒计时混用。

### 7.2 趣味表达

普通模式：“今日已赚”“正在计薪”“今日收工”。窝囊费模式：“今日窝囊费”“窝囊费累积中”“今天的窝囊费，赚到了”。午休、错误和隐私提示保持清晰的普通文案。

不因用户工资高低生成评价，不使用羞辱性提示。首版不播放音效，不定时弹通知，不自动发消息。

## 8 视觉与交互要求

界面偏安静、轻松的小工具。金额是视觉中心，其他内容帮助解释金额。建议使用暖白或深灰背景，配单一柔和强调色，借助留白和圆角形成桌面卡片感；具体视觉稿在 PRD 之后设计。

- 数字采用等宽数字特性，增长时不左右跳动。
- 进度及状态不能只用颜色区分，必须有文字。
- 文字对比度以正文至少 4.5:1 为验收目标。
- 图标按钮有可访问名称，键盘可操作，焦点清晰可见。
- 大额数字、150% 和 200% 缩放下仍完整显示。
- 尊重系统减少动态效果设置；关闭数字滚动后仍正常刷新。
- 金额区域不向屏幕阅读器逐秒播报，提供可主动读取的当前值。
- 切换隐私模式时，今日、本月、月薪、时薪和预览中的数值都隐藏，辅助功能标签也不能泄露。
- 用户主动进入工资编辑时才显示输入值；离开后继续遵守隐私模式。

## 9 隐私与数据

### 9.1 本地优先

首版不接入分析 SDK、广告或远程字体，工资及作息不离开本机。运行中的核心功能不发起业务网络请求。安装过程可能需要获取 Windows WebView2 运行时，见发布要求。

本地文件保存在系统提供的当前用户应用数据目录，不硬编码用户名或盘符。普通文件存储不宣称具有密码保护或加密能力。金额隐藏只降低屏幕泄露的概率，不承诺阻止截图。

诊断日志仅记录错误类型、应用版本和必要的系统信息，不记录工资、估算金额或完整配置。

### 9.2 最小数据结构

| 数据 | 关键字段 | 用途 |
| --- | --- | --- |
| AppSettings | schemaVersion、revision、文案模式、showFunText、privacyMode、窗口偏好、启动偏好 | 配置升级、界面同步与恢复；privacyMode跨重启保存 |
| RecurringProfile | amountMinor、工资口径、每周工作日、工作及午休分钟、timeZone | 当前计薪规则；amountMinor为1至9,999,999,999的整数分，timeZone固定Asia/Shanghai |
| DateOverride | date、dayType | date为YYYY-MM-DD；dayType为工作或休息；无记录则跟随每周规则 |
| MonthPlan | yearMonth、工作区间、总秒数、来源revision | 运行时派生数据，配置变化或月份变化后重新生成，不持久化历史快照 |
| EarningsResult | 精确今日及本月金额分数、日目标、状态、进度、理论速率 | 有效结果保留精确分子分母；无配置或零工时返回明确不可计薪状态 |
| WindowState | 窗口类型、显示器标识、逻辑位置、尺寸、可见偏好 | 多屏和缩放恢复 |

无需每秒写入“已赚金额”，它可以由月计划和当前时间确定。只在配置或窗口状态有实质变化时保存，拖动位置保存应防抖。

小窗、设置、托盘共用privacyMode。金额隐藏后，今日、本月、日目标、工资、时薪、秒薪、金额预览及对应可访问性标签统一遮蔽；今日进度百分比和工作状态可以保留。设置中的工资默认遮蔽，只有用户主动点击“编辑工资”才临时显示；退出编辑恢复遮蔽。不把薪资写入窗口标题、通知、错误信息或日志。隐私模式不改变真实计算，也不代替关闭共享屏幕的操作。

### 9.3 写入与恢复

所有持久化写入经单一服务串行执行，并携带配置修订号，拒绝过期窗口覆盖较新配置。先完整校验，再写临时文件并替换正式文件，保留最近一次有效备份。

配置损坏时尝试恢复有效备份并提示；没有可用备份则保留损坏文件，回到恢复或重新设置入口，不能悄悄用示例工资继续计算。格式升级失败时保留原文件，给出可重试的错误。

“清除本地数据”先说明范围并确认，关闭已启用的开机启动，再清除应用创建的数据及备份。失败时准确显示未完成的步骤，不能提示全部成功。

## 10 时间与异常处理

| 情况 | 必须发生的行为 |
| --- | --- |
| 关机后重新打开 | 根据当前时间重算，关机期间经过的计划工作时间计入 |
| 锁屏或睡眠后恢复 | 重新读取时间和当前月计划，不追赶遗漏的动画帧 |
| 定时器被系统节流 | 下次运行时按真实时间重算，不按回调次数累加 |
| 跨过午休或下班边界 | 在下一次可见刷新时更新状态及金额 |
| 跨日 | 按计薪时区切换今日范围；本月值继续累计 |
| 跨月 | 创建新月计划，今日及本月从新月范围计算 |
| 系统时区变化 | 固定计薪时区保持不变，显示结果不随系统时区漂移 |
| 手动调快或调慢时间 | 按新时间重算；检测到时显示一次“系统时间变化，已重新计算” |
| 系统时间回拨 | 允许金额回到新时间对应的值；跨月回拨按当前规则重算，不恢复历史薪资 |
| 没有可靠的系统时间 | 明示时间来源为本机时间；首版不联网校时，不承诺防篡改 |
| 当前窗口配置过期 | 拒绝旧修订号写入，提示刷新后重试，保留本次草稿 |
| 保存失败 | 保留上次有效配置及当前草稿，不让界面表现成已保存 |
| 置顶或开机启动失败 | 恢复实际状态并给出可操作提示，不保留假的已开启状态 |
| 托盘不可用 | 保留可见普通窗口和退出入口 |
| 多开应用 | 激活现有实例，不创建第二份计数或并发写文件 |

应用恢复、窗口显示、焦点重新获得、配置更新及每次可见刷新，都可以触发一次重算。所有这些入口调用同一个计薪函数。

## 11 多端架构设计

### 11.1 技术方案

统一技术方向为 **Tauri 2 + Vue 3 + TypeScript + Vite**，Rust 层处理桌面能力和本地文件，计算测试采用 Vitest。这个选择基于产品需要小窗、托盘和跨桌面系统支持：Tauri 使用系统 WebView，并提供跨平台壳能力，适合本项目的实现方向。实际内存和启动表现需通过原型测量。[Tauri 官方介绍](https://v2.tauri.app/start/)

首版不引入服务端、数据库、插件市场或微服务。依赖的具体小版本在启动工程时核对并锁定，不在 PRD 中指定“永远最新”的版本。

### 11.2 四层职责

| 层 | 职责 | 约束 |
| --- | --- | --- |
| 计薪核心 domain | 生成工作区间、金额计算、进度、状态、输入校验 | 纯 TypeScript；不导入 Vue、Tauri、文件系统或系统 API；可在普通Node.js环境运行 |
| 应用层 application | 草稿、月计划生成、修订校验、读取配置后的流程、多窗口状态协调 | 通过接口使用时钟、存储和桌面能力 |
| 展示层 UI | 首次设置、设置、小窗、主题与可访问性 | 消费同一个计算结果结构，不各写一套公式 |
| 平台层 platform | 窗口、托盘、单实例、开机启动、应用目录、系统事件、打包 | Windows 与 macOS 的差异收敛在这里 |

依赖方向为展示层调用应用层，应用层调用计薪核心与平台接口；计薪核心不向外反向依赖。

### 11.3 核心接口

| 接口 | 输入与输出 | 作用 |
| --- | --- | --- |
| `buildMonthIntervals(plan)` | 月计划 → 本月工作区间及总秒数 | 日历与作息只解析一次，配置变更后失效 |
| `calculateEarnings(plan, now)` | 月计划及时间戳 → 今日、本月、目标、进度、状态 | 同一输入得到同一结果 |
| `Clock.now()` | → 当前绝对时间戳 | 生产环境读取真实时间，测试环境注入指定时间 |
| `ConfigRepository.load/save` | 配置及预期 revision → 已提交的新 revision | 单写入通道、校验和恢复 |
| `DesktopBridge` | 显示窗口、置顶、托盘、启动设置、屏幕信息 | 屏蔽操作系统差异 |
| `LifecycleEvents` | 恢复、时钟变化、窗口可见性、配置变更事件 | 触发重新读取和计算 |

计薪核心的返回结果包含精确金额分数或可安全序列化的等价表示；格式化到两位小数由统一格式化模块完成。禁止在组件内用浮点数逐秒累加工资。

### 11.4 多窗口一致性

Rust 侧的配置服务维护唯一已提交配置及修订号。普通窗口和小窗都经同一命令提交修改；成功后广播包含新修订号的配置变更事件，各窗口读取最新配置并重算。

收入可以在各窗口按同一份月计划和时间独立推导，不需要每秒在窗口之间传金额。隐私状态、文案模式和置顶状态属于共享配置，切换后立即同步。托盘通过同一服务修改，不能另存一套偏好。

### 11.5 建议工程目录

以下为进入实现阶段时的组织方案，当前交付只有文档。

```text
xinwei-desktop/
  docs/PRD.md
  src/
    domain/            计薪、日历、状态和精度规则
    application/       月计划、草稿及配置协调
    platform/          桌面能力接口与 Tauri 适配器
    features/
      onboarding/
      settings/
      widget/
    shared/            格式化、通用组件与设计变量
  src-tauri/
    src/
      config/          配置服务、原子写入和迁移
      desktop/         窗口、托盘和生命周期
      platform/        Windows 和 macOS 的必要差异
    capabilities/      每个窗口实际需要的权限
  tests/
    domain/            确定性计算及边界验收

```

目录提前区分责任即可；没有平台差异的能力直接复用 Tauri，不为每个系统重复实现一套。

### 11.6 桌面能力与依赖

Tauri 提供托盘和窗口配置；开机启动、单实例等能力可使用官方插件，再由平台接口封装。持久化使用由 Rust 管理的版本化 JSON 文件及备份，以满足本产品的串行写入和恢复要求。[系统托盘](https://v2.tauri.app/learn/system-tray/)、[窗口配置](https://v2.tauri.app/reference/config/)、[开机启动](https://v2.tauri.app/plugin/autostart/)、[单实例](https://v2.tauri.app/plugin/single-instance/)

前端只开放所需的配置和桌面命令，发布版关闭开发入口，不加载远程页面。UI 不直接获得任意文件读写或任意命令执行能力。

## 12 Windows 与 macOS 的适配边界

| 能力 | Windows 首版 | macOS 后续要求 |
| --- | --- | --- |
| 计算规则与金额 | 共用计薪核心 | 同一输入必须输出同一结果 |
| 设置窗口 | Windows 标准窗口行为 | 适配原生窗口按钮、字体及键盘习惯 |
| 小窗 | 普通独立小窗，可置顶 | 验证窗口层级、全屏空间及多显示器行为 |
| 常驻入口 | 系统托盘 | 菜单栏图标，按 macOS 习惯处理菜单 |
| 关闭与退出 | 关闭到托盘，托盘明确退出 | 区分关闭窗口与退出应用，提供标准退出入口 |
| 开机启动 | 用户显式开启 | 接入系统支持的登录启动机制并反馈实际状态 |
| 数据目录 | 系统应用数据目录 | 系统应用数据目录，不复用 Windows 路径 |
| 显示缩放 | 100%、150%、200% | Retina、外接屏及不同缩放 |
| 安装与更新 | x64 安装包、覆盖安装 | 分别验证 Apple Silicon 和 Intel 的构建与安装 |
| 发布 | 首版直接分发安装包 | 确定签名、公证、最低系统版本及分发方式 |

跨平台的交付承诺是“复用计算和主要产品逻辑，明确隔离系统差异”。Windows 跑通不代表 macOS 已通过验收。macOS 必须在相应系统和硬件上实际构建、验证后才能发布。

首版不依赖毛玻璃、透明窗口或特殊桌面层级。小窗可用不透明卡片实现，降低后续系统外观适配的约束。系统 API 能力差异以适配阶段的目标版本文档及实机表现为准。

## 13 非功能要求

### 13.1 性能目标

以下是开发验收目标，尚无应用实测数据。基准环境为 Windows 11 x64、四核及以上 CPU、8GB 内存、SSD、已安装所需 WebView2；测试使用 release 包，记录具体硬件和系统版本。

| 项目 | 目标及测量口径 |
| --- | --- |
| 冷启动 | 发起启动到小窗显示有效金额且可交互不超过3秒，首次运行依赖安装及未配置向导除外 |
| 可见金额刷新 | 一秒一个计算刷新周期；正常前台情况下状态延迟不超过 2 秒 |
| 恢复与重新显示 | 获得恢复或显示事件后 2 秒内反映当前时间 |
| 常驻 CPU | 稳态五分钟平均不高于总 CPU 的 1%，排除启动、拖动及系统升级 |
| 内存 | 普通使用时应用及所属 WebView 子进程合计私有工作集目标不高于 200MB |
| 长时稳定性 | 开发阶段连续8小时；发布前连续72小时无崩溃、无金额累计漂移；预热30分钟建立内存基线，此后每小时采样，最后6小时中位值不得超过基线20MB以上 |
| 后台行为 | 所有界面隐藏时停止逐秒动画和渲染；重新显示立即重算 |
| 文件写入 | 不按秒写入收入；配置按提交写入，位置变化防抖写入 |
| 网络 | 运行中核心场景断网可完成，不等待业务网络请求 |

若原型无法达到性能目标，先根据测量定位 WebView、窗口和动画成本，再调整实现；不得以降低计薪正确性来换取指标。

### 13.2 稳定性与兼容性

首版正式测试范围为 Windows 11 x64。Windows 10、Windows ARM 和 macOS 暂不列入已支持范围；后续单独扩展测试矩阵。

必须覆盖中文及含空格用户目录、两个显示器、任务栏位置变化、不同缩放、断网、睡眠、锁屏、应用异常退出及覆盖安装。设置窗口和小窗的计薪与隐私结果必须一致。

## 15 发布与分发要求

第一版提供 Windows x64 的安装程序，安装在当前用户可用的位置，应用正常运行不依赖管理员权限。安装、启动、覆盖升级和卸载均需验证。

Tauri 的 Windows 分发支持 NSIS 安装程序和 MSI；本项目首版优先使用 NSIS 的 setup.exe。WebView2 缺失时，标准安装包明确提示并按安装流程获取运行时；如提供离线安装包，则捆绑相应运行时并单独说明体积。不能把“安装可能联网”写成“应用运行必须联网”。[Tauri Windows 安装与 WebView2 文档](https://v2.tauri.app/distribute/windows-installer/)

个人试用包与公开发布包区分标识；公开分发前确定代码签名及下载来源。首版通过下载新安装包覆盖升级，不实现应用内自动更新。

默认卸载应用可保留本地偏好以供重装恢复，卸载界面明确提示；提供同时清除本地数据的选项。用户也可先在应用内执行“清除本地数据”。自动启动注册随卸载删除。

## 17 成功标准与风险

### 17.1 成功标准

首轮邀请约5名目标用户进行试用观察，结果由人工记录，不为此给应用增加遥测。

- 至少4人能在没有口头指导的情况下，一分钟左右完成首次设置。
- 用户能说清主金额表示今天的估算收入，并知道如何隐藏金额和退出。
- 计算用例全部通过；长时运行、休眠恢复和配置恢复没有阻塞性问题。
- 试用三天后，记录有多少人愿意继续把小窗留在桌面，以及最想删除或增加的功能。
- 只有出现重复、明确的使用需求，再扩展趣味功能或统计能力。

### 17.2 主要风险与处理

| 风险 | 产品及实现处理 |
| --- | --- |
| 用户把估算理解成真实到账 | 使用“已赚 / 估算”，计算入口解释口径，不展示“到账成功” |
| 节假日导致工作日不准 | 明示默认每周日历，提供日期覆盖；后续再接入可靠来源 |
| 改日历后过去金额改变 | 保存前同时预览今日及本月变化，按钮明确说明重算 |
| 工资数字暴露 | 全局隐藏金额，默认托盘不含工资，不自动导出或分享 |
| 玩具越做越重 | 以P0为发布边界，其他想法进入候选清单 |
| 系统差异影响小窗体验 | 计算与平台分离，Windows先验证，macOS实机适配 |
| 名字或发布标识不可用 | 正式发布前核查可用性，标识确定后保持稳定 |
| 依赖或运行时与环境不兼容 | 开工时锁版本，验证安装环境和运行时分发方式 |
