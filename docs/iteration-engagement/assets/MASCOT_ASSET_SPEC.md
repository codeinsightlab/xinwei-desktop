# 薪慰角色素材投递规格 V1

## 交付状态

本包交付的是动作与资源契约、旧视觉参考图和文字素材，不是8张已完成的透明插画。manifest 中所有动作均为 planned；sourceFile=null。不得把推荐路径当作已存在的成品。

## 生产顺序

先固定一个母版的轮廓、面部比例和笔触，再从它衍生8个动作；不要分别用八段互不关联的提示生成八只不同角色。先看母版与深浅背景效果，再批量出动作。动作图只是外观，不烘焙工资、文案、按钮或交互逻辑。一个动作对应多个业务场景。

## 角色约束

沿用深色参考图中“白色圆润办公小团子”的方向，但重新明确唯一母版；无耳朵/猫耳等特征不得在不同动作间忽然改变。不要照搬现有知名IP，也不承诺AI生成自动具有独占版权。造型保留短小肢体、小眼睛、少量表情，白色/暖白实体加深色轮廓；表情略慵懒、嘴欠但友好。

深色模式可以增加细浅色外轮廓，浅色模式保留深色内线；不要简单反转整张图导致黑色角色或白色电脑。荧光黄绿只作微小点缀，紫色不要求每个动作都出现。不要拟真毛发、厚重3D、渐变光晕、复杂背景、文字、货币图案或公司Logo。

## 统一输出规格

- 每个动作独立输出1024×1024透明PNG，sRGB，四周安全留白至少12%；动作主体脚底/坐底基线尽量相同。不是把透明棋盘画进背景。
- 在64、96、128像素实际显示尺寸检查轮廓和表情；主轮廓在64像素下仍可分辨。小窗默认角色约64～88逻辑像素，不抢金额。
- 姿态尽量占画布宽70%～76%、高60%～72%；伸展动作可稍变，但不裁手脚。
- 背景需实际alpha透明，不用纯白矩形假装透明。无文字、无金额、无按钮、无UI卡片。
- 整理后的SVG也可接受，但必须是人工/程序可维护的真实矢量路径；不要声称PNG改后缀就是SVG。
- 初版静态图就足够。呼吸/淡入由CSS实现，用户关闭动效后保持静态。不要先做复杂Lottie或逐帧角色。

## 动作表

|资源键|动作|适用场景|
|---|---|---|
|`neutral`|圆润白色小团子坐着，双手自然放在身前，平静眼神。|未开工、普通设置、轻量提示|
|`working`|同一角色坐在小笔记本电脑后，微微前倾；表情平静，不表现亢奋。|开工、计数中|
|`lucky`|同一角色轻微侧头、抿嘴偷笑，一只短手做小幅庆幸动作，不使用夸张财富符号。|晚来不扣款、宽限内、免扣规则|
|`annoyed`|同一角色抱臂或托腮，眉眼轻微不服；用可爱无奈而非攻击或哭泣表达。|按分钟扣款、损失调侃|
|`resting`|同一角色趴在合起的电脑旁，闭眼，小体量杯子可选；不画文字或Z字符。|午休、休息日|
|`tired`|同一角色托腮，眼睛半闭、肩部放松；不画病容、伤口或极端疲惫。|晚收工中、昨日晚收工、连续晚收工|
|`offduty`|同一角色轻松伸展或合起电脑，表情舒展；动作不出安全区。|收工、提前结束|
|`welcome`|同一角色轻轻挥手或推来一只无标识杯子，温和表情，适合普通欢迎及关怀。|缺席回归、状态不好、温和回应|

## 文件位置和交接

参考图放在 docs/references/xinwei/；正文说明每张图的用途，不给Codex一堆无标题图片自行猜。正式素材放 src/assets/mascot/，文件名对应动作键，如 working.png、lucky.png。最终路径由项目结构决定，但只能在一个资源映射中适配。

目前母版未确认时，Codex可沿用已有正式素材；若没有，用同一个本地SVG占位和正确pose属性完成交互，不得宣称美术完成。正式图片到位后替换映射和资源即可，不改计薪、事件规则或对话。

## 正式生成时可复用的母版描述

以下仅是将来素材生产的文字规范，本次未调用图像生成：

“为薪慰 Xinwei 桌面工具设计统一办公角色母版。一个原创、白色圆润的简约小团子，短小肢体，小眼睛，带一点慵懒但友好的表情，现代手绘线描与轻幽默编辑风，清晰深色轮廓，形状少而有辨识度。适合炭黑和暖白两种UI背景，荧光黄绿色只作极小点缀。角色是陪用户吐槽的同事，不是老板、儿童玩具或知名动漫角色。独立透明背景，1024×1024，统一安全留白，正面或轻微三分之二视角，无文字、无UI、无Logo、无复杂背景。”

母版确认后，以同一母版作为图片参考，每次只改变动作表中的动作；保留轮廓、脸型、眼睛间距、线宽、身体比例和画面基线。不要给生成器整张工作台让它顺便重画角色。

## 素材验收

确认同一角色、alpha透明、边缘无白底方框、实际小尺寸可读、深浅背景都可见、无裁切、无内嵌文字。标注来源及授权说明，不臆造“已查重”“原创无侵权”结论。
