# 任务：薪慰 Xinwei——开工/收工仪式、迟到约定、回归关怀与角色互动迭代

## 0. 执行目标与边界

这是现有产品的一次增量迭代，允许修改代码、必要的数据结构、测试及文档。先读取仓库 AGENTS.md、现有 PRD、视觉规范和实现，再开始工作。不要只输出方案，也不要重建项目、替换已能工作的技术栈或无关重构。

产品不是考勤系统，而是有工资计数功能的桌面搭子。每天主动来 App 点一次“开工”，才开启当天的工资展示；点“收工”，获得今日回顾。这个机制是互动仪式，不是验证真实到岗。金额均为按用户设置的趣味估算，不代表实际发薪、到账或公司认可的扣款。

本任务覆盖旧版“自动激活每天计数”和“不保留每日记录”的相冲突设计，其余既有功能继续复用。不得为过时逻辑额外保留并行的自动计薪模式。必要迁移保留用户配置；没有真实操作记录的旧数据不得伪造为开工/收工记录。

本轮范围：主动开工/收工、默认不扣款及按分钟扣款、只统计晚收工时长、昨日反馈、缺席后欢迎与可选补算、可接话的短互动、角色状态、统一素材入口、关键测试。

不做：公司考勤、位置/键鼠监控、病假事假审批、补卡审核、薪资法律计算、账号服务端、AI 在线聊天、连续签到惩罚、积分货币、排行榜、复杂成就、复杂工资账本、新增独立工作台。主结构仍为“小窗＋设置＋按需出现的互动面板”。

下面给出的数值阈值、跨日收尾和数据生效规则是本次为实现闭环补充的默认方案；集中定义、写入文档，不宣称是企业通用工资制度。产品优先保证轻松、透明、不误导。

## 2. 用户主流程

未开工：显示“今天还没开张”、统一角色及主按钮“开工”。金额用“—”或“待开启”，不是断言用户今天赚了 0 元。打开应用、登录系统、显示小窗本身不会自动开工。

点击开工：先校验并可靠保存当天开工事件，再开启计数和展示互动。即使用户关闭对话、不点回复，开工也已经成功。保存失败则保留未开工状态并提示重试，不能先庆祝成功。

进行中：计划工作区间内累积；午休自动停止金额增长；计划下班后金额封顶，切换“已到约定下班时间”，同时展示估算晚收工时长。角色通常保持静态，不持续制造打扰。

点击收工：保存结束事件，停止当天累积及晚收工计时，展示一张轻量收工卡。包含今日估算金额、按设置扣减（有才显示）、晚收工时长（有才显示）、一句情境反馈及可选回复。回复不影响金额。

当天结束后保持收工状态。再次点开 App 不重复开工、不重复扣减。提供“刚才点错了，继续”轻量撤销入口，复用同一天记录，不重置第一次开工、不重复抽取奖励或扣款；早收工撤销后按同一规则重新推导。

本轮每天最多一个开工周期，不做多段考勤。首次安装前的日期不自动生成缺席、迟到或工资记录。

## 3. 工资与迟到规则：必须避免重复扣减

### 3.1 计薪基本语义

“从点击开工才开始显示”不等于“不扣款模式仍少算迟到时段”。未开工时不展示已激活收入；开工成功后补齐当天截至此刻的计划内工资进度。之后继续按时钟计算。

继续复用固定月薪按月计划工作秒数分摊的纯计算核心。固定计薪时区 Asia/Shanghai；区间左闭右开；午休不计薪。

定义：
- S：规则快照中的月薪，单位整数分。
- H：同一快照下本月计划工作总秒数。
- I：当天计划工作区间集合。
- E(t)：I 中截止 t 已经过的工作秒数。
- t：ACTIVE 时为当前时间，CLOSED 时为有效收工时间。
- G(t)=S×E(t)/H：精确的计划内累积金额。
- D：首次开工确定并保存的用户自定义扣减。
- N(t)=G(t)−D：今日净估算。

无开工或主动补算记录，不对该日输出有效已激活工资。H=0 时显示可修复异常，禁止 NaN/Infinity。

不扣款时 D=0，晚点击不再减少 G。开启扣款时只从 G 减一次 D，不再剔除首次点击之前的计划工时。提前收工停止后续增长；提前开工不增加约定开工之前的工资。午休不增加工资。计划下班后无论多晚收工，G 不超过当天计划目标。

UI 至少在详情中区分“计划内累积 / 按设置扣减 / 今日估算”，避免把概念混成已到账金额。N 可以为负，使用统一负金额格式，不擅自归零吞掉差额。金额内部精确运算，统一最终格式化；正数向下取分，负数对绝对值截断到分再加负号。不得逐秒舍入累加。

### 3.2 迟到约定

用户可选：NONE（默认不扣款）、PER_MINUTE（按分钟扣减）。默认宽限 0 分钟；可设 0～60 分钟。启用 PER_MINUTE 时必须明确输入每分钟金额（0.01～9999.99 元、最多两位小数），不能偷偷用推导时薪替代。

本轮把“晚来分钟”定义为从当天第一个计划工作区间开始，到首次点击开工期间经过的计划工作秒数，不含午休。这是 App 的约定差，不推断实际到岗。

- lateSeconds = E(firstStartedAt)。提前点击为 0。
- chargedSeconds = max(0, lateSeconds − graceMinutes×60)。
- chargedMinutes = ceil(chargedSeconds/60)，不足一分钟按一分钟；恰好在宽限边界不扣，超过一秒按一计费分钟。
- NONE：D=0；PER_MINUTE：D=chargedMinutes×perMinuteMinor。

普通状态显示精确到分钟/秒的晚来时长；扣款详情显示计费分钟，二者不得混用。设置预览要解释宽限、午休排除和不足一分钟处理。

晚于当天最后计划下班时间才首次打开，不自动认定全天迟到并罚款。显示“今天已经到收工时间了，要补上今天的进度吗？”，走主动补算或跳过。休息日不产生迟到、不显示完成 100%，也不偷偷新增工作时段。

用户第一次开工的迟到结果当天固定。跨窗口重复点击、重启、再次打开、回复对话、撤销收工均不能重复扣减。

### 3.3 设置生效与历史

每个已激活日期保存计算所需的最小规则快照：月薪、当月总计划秒数、当日区间、时区、迟到规则及版本。修改设置不回写已经开工、收工或补算的日期；默认应用于尚未激活的日期。当前日已激活时明确显示“今天已开启，修改从下一个未开启的工作日起使用”。不要新增复杂月内调薪或历史修订界面。

本月摘要改为“本月已记录估算”：累计本月已激活及主动补算日期的金额；无记录日期不自动计入，也不称为零真实收入。由于未开启日期、提前收工、扣减和规则调整，本月记录不保证等于配置月薪，需有简短说明。

## 4. 晚收工、未收尾与恢复

固定月薪不因晚收工而增加。估算晚收工秒数 = max(0, min(now或收工时间, 当日结束) − max(约定下班时间, 首次开工时间))；仅 ACTIVE/CLOSED 且非补算记录可有此值。

展示可以说“今天晚收工 47 分钟”，详情说明“按本次开工/收工操作估算，不代表真实工时”。不能声称自动识别到用户仍在工作。工作中关闭应用、隐藏窗口、休眠不自动收工；重开按既有事实和当前时钟重算。

跨到下一自然日仍未收工：旧日置为 PENDING_END，旧日计划内金额按日末封顶；不跨多天继续累积加班，不把未知结束时间当成确定加班。次日提供非阻塞小提示：
“昨天忘了说再见，要怎么收尾？”
- “按约定时间收工”：结束时间取 max(约定下班时间, 首次开工时间)，标记为用户确认的估算收尾。
- “选个大概时间”：只允许该日、且不早于首次开工的时间，标记 estimatedEnd；不是补卡审批。
- “先不管”：保留待收尾，不阻止今天开工。

待收尾记录不用于“昨天加班很久”或连续晚收工文案；本月金额可包含其已封顶估算，但必须标注有待收尾日期。系统时间回拨不自动再发事件或重扣，计算夹到有效区间，必要时给普通时间异常提示。

## 5. 缺席后的回归关怀与展示补偿

这里的缺席只指没有来 App 互动，不是现实缺勤。

仅在上次真实互动之后、当前日期之前统计已过去的计划工作日。排除正常休息日、首次使用之前的日期；没有历史记录时不编造“昨天”。示例分档：漏 1 个工作日轻问候，2～4 个工作日展示可选近况，5 个及以上欢迎回来并可确认作息。阈值集中为可测试常量，不增加用户设置负担。

“这两天没碰面，最近还好吗？”
- 最近有点忙 → “看来不是没上班，是忙得没空看自己赚了多少。”
- 休息了一阵 → “挺好，那几天留给生活，不用来我这儿补作业。”
- 状态不太好 → “那今天不贫了。你按自己的节奏来。”
- 忘了打开 → “还以为你发财了，不用看这点工资了。”
- 直接开工/略过 → “欢迎回来，今天从这里开始。”

不要求解释、不索取诊断或请假原因；不保存健康明细。可仅保存当天到期的 gentleTone 标志，之后减少调侃。开工无需先回答。长时间缺席不发羞辱、掉级、角色生病/快饿死等内疚诱导。

可选补偿：“漏看的这几天，要按原作息补上工资进度吗？”本轮仅支持本月、首次启用之后、尚无激活记录的计划工作日。

先列日期、将采用的规则和金额预览，再一次确认。不能悄悄补算；不能覆盖 ACTIVE/CLOSED/PENDING_END；不要求补上下班时间。优先使用已有该日规则依据；没有则说明“按当前设置估算”，不能谎称历史配置已知。

补算记录 source=ESTIMATED_CATCHUP，增加展示累计，但不产生迟到扣减、加班、准时成就或虚假真实访问。每个日期最多一条；重复执行幂等。允许从补算结果撤销本批补算，不影响真实互动记录。批处理持久化失败时不得一部分成功却提示全部成功。

跨月缺席可以欢迎，但不自动重建以前月份或生成财务账本；用户跳过补算也不受罚。

## 6. 角色与双向互动

角色性格：嘴欠但站在用户一边，像懂打工人的同事；普通时一起庆幸、吐槽，用户表达不舒服时收住。不要 HR 训话、励志鸡汤、收入攀比、鼓励报复或欺骗。公司相关吐槽限定在用户设定的玩法里，不断言现实雇主真的实行该规则。

基础日程状态：待开工 / 工作中 / 午休 / 晚收工中 / 已收工 / 休息日 / 配置异常。

短时情绪：neutral、working、lucky、annoyed、resting、tired、offduty、welcome。日程状态和情绪分开建模；不能因角色变困改变金额，也不能因用户点搞笑回复增加工资。

场景至少覆盖：
1. 保存不扣款规则：“碰上好人家了，迟到还不扣钱。”
2. 保存按分钟扣款：“发工资按月，扣工资按分钟。精明。”
3. 保存宽限：“公司和被窝，各退了 {graceMinutes} 分钟。”
4. 提前/准时开工：“人到了，精神稍后抵达也行。”
5. 晚来不扣款：“晚来 {lateMinutes} 分钟，工资照算。这波薅到了。”
   回复“低调低调”→“懂了，这事不写进年终总结。”
   回复“也就这点好了”→“懂，优点已经介绍完了。”
6. 晚来有扣减：“天崩开局，班还没上，先消费 {deductionAmount}。”
   回复“这班非上不可吗”→“我支持你，账单暂时持保留意见。”
   回复“先把钱挣回来”→“行，计数器开了，我陪你盯着。”
7. 宽限内：“擦边进场，一分没少。”
8. 昨天有扣减、今天未扣：“今天零元入场，舒服。”
9. 昨天已确认晚收工较久：“昨天走得挺晚，今天就别跟昨天比了。”
10. 准点收工：“电脑可以下班，你也可以。”
11. 提前收工：“今天先到这里，剩下的时间归你。”
12. 晚收工：“今天又多待了 {overtimeMinutes} 分钟。记下了，不拿它当勋章。”
13. 最近连续晚收工：“最近几次都收得有点晚，明天争取早点散场。”
14. 漏了收工：“昨天忘了说再见？没关系，今天接上。”
15. 缺席回归及可选近况回应，见上一节。
16. 休息日打开：“今天不营业，连窝囊费也歇一天。”
17. 收工后又打开：“今天不是收工了吗？我看看是谁又回来了。”

附带文案库提供更多变体。每个常见事件至少 3 个短句，但不要逐秒抽随机。用 eventId、最近展示记录和可注入随机种子避免重复；同一事件跨重绘/重启保持已选结果。

单次只选一个主要情境，优先级：保存/时间/配置错误先用普通明确提示；用户主动表达状态不好优先温和回应；回归欢迎；昨次明显晚收工；本次扣款或不扣款；普通开工。扣减数字是事实区，不会因为主要情绪是欢迎而隐藏。

“昨日反馈”实际指最近一个有已确认结束记录的计划工作日，不跨无记录日期编造连续表现。连续晚收工默认最近连续 3 个计划工作日均有已确认记录且各晚收工不少于 60 分钟；缺失或待收尾即不满足。只描述记录，不诊断用户劳累。

每次开工/收工最多一轮主互动、一轮可选回复，不做无限聊天。配置保存最多一条轻提示；一天回归问候一次。主动点击角色可给一条低频彩蛋（至少 30 秒冷却），不影响业务。关闭趣味反馈后所有功能正常、保留中性成功提示。

## 7. UI：在现有视觉上增量实现

沿用已有统一视觉，不另起三套设计。深色参考的炭黑层级、黄绿色主强调、手绘角色是本轮重点；已有浅色模式保持对应语义，不借本轮重做全部页面。只保留小窗和设置，不新增独立工作台、榜单或多张大金额卡。

小窗可以保持紧凑，但新增“开工/收工”主操作必须可见、可键盘访问。不要把开工藏在更多菜单。不得为了硬塞 280×150 而缩小金额和触控区域；必要时可增高，记录实测尺寸。

欢迎、接话和收工卡使用可关闭的小型 popover/辅助面板，首版不要求花哨原生动画。不将完整对话强塞进常驻小窗。用户主动点击可以聚焦弹层，金额刷新/自动状态变化不抢焦点。弹层有关闭入口，Escape 可关闭；含可点击回复时不自动几秒消失。

一张界面最多一个角色和一种轻装饰。金额第一、状态第二、角色第三。按钮须为真实按钮，状态点不是播放按钮，不暗示需要手动启动午休计时。

设置新增“开工约定”小节：不扣款/按分钟、每分钟金额、宽限、清晰预览；“互动”小节：趣味反馈开关。修改规则保存成功才触发角色评论。保存失败保留草稿和上次生效值。

隐私模式覆盖：主金额、扣减、收工卡、规则预览、补算预览、对话变量、Toast、托盘、标题和可访问性文本。例如金额隐藏时把“先消费 ¥10.00”替换成“今天先交了点入场费”。不可只用 CSS 盖住文字而让 aria-label 泄露。用户主动进入编辑工资/扣款字段可展示输入，离开恢复隐藏。

文案统一用“累积/估算/记录”，不出现“到账成功”。“晚来”和“加班”在说明中限定为 App 内约定/互动估算。

## 8. 素材投递与组件接口

本交付包 references/ 是旧效果图，只能参考，不能作为正式角色透明素材。assets/mascot.manifest.json 中 status=planned 的资源尚未绘制，不得声称已交付。

用一个角色母版和 8 个动作覆盖多个事件，而不是一个文案一张图片。动作键：neutral、working、lucky、annoyed、resting、tired、offduty、welcome。

实现统一 <Mascot pose="..." /> 或等价组件与集中资源映射。素材路径、动作名、深浅色适配、fallback 不散落在业务代码。

正式运行素材：独立透明 PNG/WebP 或人工整理的 SVG；不得把效果图裁块当作已验收的透明角色，不得把整张参考图铺作 UI 背景，不得用 Emoji 冒充正式角色。素材无嵌入文案、金额或按钮，文案由真实 UI 渲染。

优先复用仓库已批准的母版。若没有正式素材，用同一个简洁本地 SVG 占位完成交互，显式列入未完成美术项；素材缺失不能阻断计数/开工/收工/测试。不能自动联网采集相似 IP，不能假造完成 8 张正式插画。详情见素材规格。

## 9. 工程与数据约束

复用已有月度区间、精度、Clock 和存储服务，扩展输入为“规则快照＋日期互动事实＋当前时间”。不在 UI 组件重新写工资公式。

最小持久化对象包括：
- EngagementDay：唯一 workDate、首次开工时间、收工时间、状态、source、规则快照、扣减依据、估算收尾标记、revision。
- InteractionReceipt：唯一 eventId、sceneId、已选文案、回复结果/是否跳过，用于重启与跨窗口去重；不要记录健康描述。
- CatchupBatch：仅必要的补算批次及日期关联，支持幂等和撤销。

状态如 NOT_STARTED（可推导）、ACTIVE、CLOSED、PENDING_END、ESTIMATED；不得把未操作推断成 ABSENT。clockIn/clockOut 可作为内部命令名，对外推荐“开工/收工”，不建设考勤模型。

所有影响金额的命令通过同一权威服务串行提交；持久化成功再广播到窗口；开工、收工、补算有幂等键和日期唯一约束。两窗口同时点击只能成功一次，不重复互动或扣款。视图不分别写整份配置。

使用现有 JSON/SQLite 方案即可。已有 JSON 能安全处理小量记录就沿用，不为这次功能强制迁移数据库；已有数据库就复用。原子写入、迁移、备份与失败恢复必须保留。敏感金额和完整配置不写日志。

历史记录不需要每秒保存派生金额；通过快照和事件重算。关键操作持久化，动画状态临时保留。Domain 与互动选择器分别为纯函数，展示层只消费结果。用固定 Clock 和种子可复现测试。

多窗口配置、隐私、主题及当天状态一致；一个事件只在触发窗口展示互动，其他窗口同步数据但不同时弹第二遍。不可抢焦点自动拉起窗口。

保留 Windows 优先、macOS 平台边界；未经对应系统实测，不声称通过跨平台发布验收。

## 10. 固定验收样例与场景测试

基础：2026-11-03，Asia/Shanghai，月薪 ¥16,800，周一至周五，09:00–12:00/13:00–18:00，无日期覆盖；本月 21 工作日、168 小时，理论时薪 ¥100。

至少覆盖：
1. 09:10 打开但没点开工：待开启，无扣减事件、无自动激活工资。
2. 09:10 点击，NONE：计划累积 ¥16.66、扣减 ¥0.00、净估算 ¥16.66；14:30 为 ¥450.00。
3. 同时刻点击，PER_MINUTE=¥1、宽限0：一次扣减 ¥10.00，净估算 ¥6.66；14:30 为 ¥440.00。不能额外少算那10分钟。
4. 宽限5分钟：09:05:00不扣；09:05:01计1扣减分钟；午休不计入迟到的有效计划秒数。
5. 提前开工：计划开始前金额0；09:00后才增长。午休开工可激活当天此前计划累积，但午休期间不增长。
6. 高扣减金额可出现负净值，格式与精确计算正确；隐私模式不泄露负数或扣减。
7. 12:30金额保持上午值；13:00恢复状态；18:00起工资封顶。
8. 18:47收工：晚收工47分钟，工资不比18:00更多。
9. 17:30收工：工资停在该时点，没有负加班；撤销收工不重复开工或扣减。
10. 重复点击、多窗口竞争、重启：同日一条事件、一次扣减、一次主互动。
11. 保存失败：不展示开工成功或已收工，不丢草稿。
12. 隐藏/退出/休眠后重开：从记录和时间重算，不追补动画帧；不是靠运行时长累加。
13. 跨日未收工：待收尾，不无限加班，不阻塞今天开工；未知结束不生成连续加班反馈。
14. 普通周末不生成缺席关怀，首次使用不生成历史缺席。
15. 连续漏用后回来：可跳过近况直接开工；选择状态不好只切温和文案，不保存健康明细。
16. 同一批补算重复点击：每日期只一条估算记录，不罚款、不假造出勤或加班；失败不假报全成功；撤销不碰真实记录。
17. 规则修改不改变已激活日；本月摘要由实际记录和补算组成，不静默填满整月。
18. 隐私同步覆盖对话、收工、补算、设置预览、aria 文本及托盘。
19. 关掉趣味反馈、缺少正式图片、减少动态效果开启时核心功能仍完整。
20. 真实小窗在100%/150%/200%缩放、长金额、长短文案下无裁剪，操作可达。
21. 系统时间回拨不制造新事件/二次扣款；零工时配置显示明确错误。
22. 文案场景正确：休息日不祝贺准时、状态不好不继续挖苦、有扣减事实不会被欢迎文案掩盖。

不要继续沿用旧图“11月3日第一次启动，本月自动有前一天工资”的样例。本轮未激活日期不自动拥有记录。
