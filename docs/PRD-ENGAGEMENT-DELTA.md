# 薪慰互动迭代

本次增量以 [完整交接规格](iteration-engagement/CODEX_ITERATION_PROMPT.md) 为准。以下约定替代 PRD 1.1 的自动展示、整月回算、舍入和无每日记录条款。

| 用户操作 | 保存的事实与展示 |
| --- | --- |
| 打开小窗 | 等待开工。首次使用之前的日期不生成记录。 |
| 开工 | 保存一次当天开工、当日作息区间、月计划秒数、工资和扣减规则。展示截至当前的计划内累积。 |
| 晚来 | 默认免费。按分钟时，从已过的计划工作秒数中扣掉宽限，剩余秒数向上取整为计费分钟。扣减仅在首次开工时确定。 |
| 收工或继续 | 收工后冻结金额，晚收工只记时长。当天继续沿用原快照与首次扣减。 |
| 跨日未收尾 | 计划内进度封顶，结束时间待确认。可以先开启新的一天。 |
| 回归与补算 | 允许跳过近况。只补用户确认的本月计划日，按当前设置估算，可按批次撤销。 |
| 修改设置 | 已有记录保留快照，新规则用于下一个未开启的日期。本月摘要仅累计有记录的日期。 |

金额以整数分乘工作秒数，先减去扣减的精确分子，再除以月计划秒数，最终向零截断。例：月薪 ¥16,800、月计划 168 小时，09:10 开工的默认估算为 ¥16.66。每分钟扣 ¥1 时，记录扣减 ¥10.00，净估算为 ¥6.66。午休不累计，18:00 后计划内金额封顶。

数据存放在本机原有配置及备份中。旧配置首次进入时建立空的互动记录。Windows 的写入沿用互斥锁、版本检查、原子替换和保存后广播。每个窗口只展示自己成功提交的事件。日状态、动作键、事件与已选文案分别记录，金额遮罩也应用于插值文案。

正式美术仍待交付。动作及替换要求见[角色素材规格](iteration-engagement/assets/MASCOT_ASSET_SPEC.md)。

## 2026-11-04 共享窗口与互动语义调整

以下规则适用于 Windows 与 macOS，共享 UI、窗口角色及持久化实现；仅系统 API 差异在 `src-tauri/src/window_platform.rs` 适配。

- 悬浮窗采用 24px 圆角和透明外角，保留不透明内容表面；直接显示金额隐私切换、更多操作和隐藏按钮。
- 今日明细、本月记录及无待选回复的普通反馈，点击非交互内容即可收起，Esc 同样有效；文本选中、展开记录、点击按钮不误触收起。补算、收尾和待选回复仍要求明确操作；任何点击收起都不能自动确认金额、日期或结束时间。
- 趣味反馈开关只控制可选互动及反馈文案，不切换主界面布局或角色组件。角色按钮关闭时保持位置、大小和不透明度；开工、收工和计薪不受影响。
- 悬浮窗与设置是两个独立原生窗口，共用同一应用状态与 Store。仅悬浮窗置顶；macOS 悬浮窗跨 Space，并允许作为全屏辅助窗口；设置仍为普通窗口，并禁止两个窗口自动合并标签。共享语义是跨应用悬浮，Windows 跨虚拟桌面没有在本次新增专用系统实现，不宣称已支持。
- 普通设置保存留在设置页；只有首次设置完成才展示小窗并隐藏设置。关闭任意窗口只隐藏，首次设置也不退出。未保存草稿先确认；正常退出通过托盘、系统应用菜单或系统明确退出操作。托盘不可用时保留可见窗口及明确退出后备入口。

## 2026-11-04 低打扰时间节点互动

用户新增要求：午休开始、午休结束和下班也能互动，但须低频、尊重趣味反馈与小窗隐藏状态，并且跨平台共享、不能改变计薪。本节替代上一轮“不在时间节点主动提示”的行为。

### 共享行为

- 仅为当天已经用户主动开工、仍为 ACTIVE 的日期触发。读取当天冻结的区间快照；关闭午休或区间无间隔时没有午休节点。未开工、休息日、补算日、已收工日不触发。
- 仅在持续可见时跨过节点，允许最多10秒的连续观察间隔；初次打开、重显、跨日、睡眠或明显跳时不补弹。原生层只读取 widget 的可见/最小化状态，并广播显示/隐藏事件；没有显示、聚焦、恢复或系统通知操作。无法确认可见性就跳过。
- 每个日期的每个节点最多一次、每天最多三个；两个自动互动至少间隔30分钟。已有面板、菜单、其他保存操作或错误提示时跳过；最近30秒有输入或点击也跳过。跳过不排队，不在用户空闲后补发。
- 采用小窗内不抢焦点的非模态短提示，点击或8秒后收起。开启隐私模式仍可提示，文案不包含金额变量。关闭趣味反馈立即收起已有自动提示；重新开启不补发。
- 提示只记录展示占用回执。下班提示不自动执行收工，不改变 day.state、endedAt、firstStartedAt、revision、快照、扣减、最后访问/互动日期或收入。互动回执不能作为现实考勤、实际下班或实际收入的事实。
- 多窗口共用原有串行 Store 和 revision 检查；只有成功占用回执的窗口有资格显示。占用后再次确认可见性/开关/遮挡条件，避免保存期间隐藏仍显示。极端竞争中允许回执已占用但最终未展示，优先保持安静，不补弹。
- 辅助回执保存失败只保留诊断、安静跳过，不阻塞主功能或显示自动错误横幅；用户主动保存的错误反馈保持原有语义。

### 实现与数据兼容

- `src/domain/checkpoints.ts`：快照节点、连续观察、每日幂等和30分钟冷却。
- `src/domain/engagement.ts`：独立 checkpoint 元数据分支，绕开手动动作的日期/工作日状态转换。
- `src/application/checkpoint-interactions.ts`：共享生命周期、可见性检查、面板/输入抑制、8秒收起及资源清理；仅 ACTIVE 且开关开启时，每秒最多一次只读可见性查询，成功占用后再确认一次，不在循环中写文件。

## 2026-11-04 悬浮窗顶部拖动修正

### 发现与实现

- 源码确认：旧 header 仅26px高，外侧12px顶部留白和底部间隔不属于拖动区；视觉上的整段顶部与实际命中区域不一致。原配置还使用 macOS 默认 `acceptFirstMouse: false`，未激活小窗的首次点击可能只激活窗口。
- 顶部实际命中区域扩展为50px，包含留白、标题及其文字节点；通过负 margin 和等量 padding 保持品牌、按钮、正文起点及304×250整体尺寸不变。图标按钮及其容器明确排除，正文和弹层不作为拖动区。
- Windows 使用 Tauri 当前锁定版本支持的 `data-tauri-drag-region="deep"`；macOS 在同一 DOM 区域处理鼠标按下，排除按钮/SVG/链接/输入等交互内容，阻止重复进入标准拖动脚本。
- 仅 widget 开启 `acceptFirstMouse`，并关闭最大化；设置窗口沿用系统标题栏。
- macOS 专用 `start_widget_drag` 只接受 widget 调用，在 AppKit 主线程执行。通过当前屏幕鼠标位置转换为窗口坐标构造有效鼠标按下事件，仅在物理左键仍按住时执行 `performWindowDragWithEvent`，避免请求在松开后开始拖动。不依赖跨异步 IPC 后可能失效的 `NSApp.currentEvent()`；不安装全局鼠标监听器、不申请新的系统权限、不改变收入或窗口独立性。
- 时序风险来自本地依赖 `tao 0.37.2` 的 `drag_window` 实现：当前事件为空时只记录警告并返回成功。本轮没有捕获该警告，不能把该风险描述成已证明的唯一运行根因。

## 2026-11-04 小窗菜单自动收起

用户要求“三个点”菜单在点击弹出区域之外时自动隐藏。共享 `App.vue` 使用菜单和触发按钮的元素引用，在捕获阶段识别区域外 pointerdown；不拦截默认动作或事件传播，因此外部按钮仍能完成原操作。再次点击三个点正常切换，菜单内部点击和菜单项操作保留。

窗口失焦、窗口隐藏/重显、键盘焦点移出菜单区域、Esc 和文档隐藏也会收起菜单。Rust 为 widget 的 `WindowEvent::Focused(false)` 广播 `widget-blur`，补齐原生焦点来源；浏览器 blur 为共享后备。监听器随组件销毁释放。此行为只收起菜单，不隐藏小窗、不变更计薪、置顶偏好或数据 schema。

### 实际发现与修正：原生Quit绕过

首轮原生试验发现只拦截Tauri RunEvent::ExitRequested不足以保护当前锁定版本的AppKit菜单：原生Quit使用terminate:，Tao 0.37.2代理没有applicationShouldTerminate:，导致测试草稿丢弃并退出。此轮失败不计通过。修正为在既有Tao代理类添加缺失的可选applicationShouldTerminate:，返回TerminateCancel并进入共享协调，最终写入成功才真正退出。保留同一代理的其他方法/布局，不替换已有方法；若未来依赖已实现该方法则明确报错，要求升级时重新验收。新增直接objc2声明复用已锁定0.6.5，没有升级依赖或注册全局快捷键。

API核对基于锁文件及本机registry对应源码：tauri 2.12.5的RunEvent/ExitRequestApi；tao 0.37.2的app_delegate.rs；muda 0.20.0原生Quit的terminate:；objc2-app-kit 0.3.2生成的NSApplicationTerminateReply及代理签名；objc2 0.6.5的class_addMethod。平台配置机制参考[Tauri配置文档](https://v2.tauri.app/reference/config/)，不假设窗口数组按label深合并，改由角色配置构建器注入少量原生参数。
